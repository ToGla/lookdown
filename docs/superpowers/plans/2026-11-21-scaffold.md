# Project Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A minimal, runnable Tauri 2 + Vite + TypeScript skeleton: one window titled "lookdown", size-optimized release build, Vitest and `cargo test` wired up.

**Architecture:** Generate the official `create-tauri-app` vanilla-ts template into a scratch directory, copy it into the repo root (the root is not empty), then strip demo content. Frontend lives at the repo root, Rust in `src-tauri/`.

**Tech Stack:** Tauri 2, Vite, TypeScript (no UI framework), pnpm, Vitest, Rust (tools from `mise.toml`).

**Spec:** `docs/superpowers/specs/2026-11-21-scaffold-design.md`

## Global Constraints

- No UI framework; vanilla TypeScript only.
- Cross-platform code only; no Windows-only paths or APIs.
- Identifier `com.lookdown.app`, product name `lookdown`, exactly one window titled `lookdown`.
- Release profile: `opt-level = "s"`, `lto = true`, `codegen-units = 1`, `strip = true`, `panic = "abort"`.
- Out of scope: CodeMirror, tabs, single-instance, file association, installer tuning, menu bar.
- Shell commands run in PowerShell on Windows; the commands themselves are cross-platform.

## Review Focus

1. Leftover template plugins (`tauri-plugin-opener`) or their capability permissions: must be fully removed, or the build fails / ships unused code.
2. Leftover demo assets referenced from `index.html`/`main.ts` (logos, greet form): a dangling reference breaks `pnpm build`. Covered by the Task 1 build step.
3. The `[profile.release]` must sit in `src-tauri/Cargo.toml` (the only Cargo manifest); a profile in any other place is silently ignored. Covered by the Task 1 manifest test.
4. Generated files with CRLF or icons treated as text: `.gitattributes` normalizes sources to LF and marks `*.ico`/`*.icns`/`*.png` binary; `git status` after `git add` must show no warnings about line endings changing in icons.
5. `pnpm tauri dev` needs Vite on the `devUrl` port with `strictPort`; keep the template's `vite.config.ts` server settings intact.

- [ ] **Step 3: Write the failing config test in `src-tauri/src/lib.rs`**

```rust
#[cfg(test)]
mod tests {
    use serde_json::Value;

    fn conf() -> Value {
        serde_json::from_str(include_str!("../tauri.conf.json")).unwrap()
    }

    #[test]
    fn app_identity_matches_spec() {
        let c = conf();
        assert_eq!(c["productName"], "lookdown");
        assert_eq!(c["identifier"], "com.lookdown.app");
        let windows = c["app"]["windows"].as_array().unwrap();
        assert_eq!(windows.len(), 1);
        assert_eq!(windows[0]["title"], "lookdown");
    }

    #[test]
    fn release_profile_is_size_optimized() {
        let m: toml::Table = include_str!("../Cargo.toml").parse().unwrap();
        let r = &m["profile"]["release"];
        assert_eq!(r["opt-level"].as_str(), Some("s"));
        assert_eq!(r["lto"].as_bool(), Some(true));
        assert_eq!(r["codegen-units"].as_integer(), Some(1));
        assert_eq!(r["strip"].as_bool(), Some(true));
        assert_eq!(r["panic"].as_str(), Some("abort"));
    }
}
```
Add `toml` as a `[dev-dependencies]` entry in `src-tauri/Cargo.toml`.

- [ ] **Step 4: Run it to verify it fails**

Run: `cargo test --manifest-path src-tauri/Cargo.toml`
Expected: `app_identity_matches_spec` fails on the window title (template uses the project name casing / differs) or `release_profile_is_size_optimized` panics on missing `profile`.

- [ ] **Step 5: Trim and configure**
